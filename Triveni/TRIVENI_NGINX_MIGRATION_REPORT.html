System Architecture: Before vs. After

In the original implementation, the system operated as three independent, isolated development servers running on different local ports with restrictive CORS headers. The updated implementation unifies all web applications, REST APIs, and WebSockets behind an enterprise-grade Nginx reverse proxy running on standard HTTP Port 80, backed by a pre-packaged standalone Node.js binary.

Original Architecture (Pre-Nginx) Development Mode
  • 🔴
    Multi-Port Access: Admin UI on :5173, Operator UI on :5180, Backend on :5050. Users must remember port numbers.
  • 🔴
    CORS Vulnerabilities: Backend was locked to http://localhost:5173. Other LAN tablets or IP addresses were rejected with CORS errors.
  • 🔴
    Dev Server Dependency: Relied on vite and supervisor running in open CMD terminals. If a window was closed, the MES went down.
  • 🔴
    Node.js Prerequisite: Customer machines were required to have Node.js v20, npm, and build toolchains pre-installed.
Current Architecture (Nginx Production) Production Grade
  • 🟢
    Unified Port 80 Ingress: Everything accessible through http://<IP>/ (Admin) and http://<IP>/operator/ (Touchscreen Kiosk).
  • 🟢
    Reverse Proxying: Nginx handles static file caching, gzip compression, SSL termination readiness, and proxies /api/ & /socket.io/ seamlessly.
  • 🟢
    Standalone Executable: Backend compiled into triveni-backend.exe via @yao-pkg/pkg — zero Node.js installation required on production server.
  • 🟢
    Background Windows Services: Automated with NSSM for silent startup at boot, crash auto-recovery, and 10 MB stdout/stderr log rotation.

Prepare Backend for Binary Packaging & Multi-Origin CORS

Install @yao-pkg/pkg as devDependency in backend/package.json, configure the build:exe npm script, adjust asset mapping for pdfkit and migrations, and update server.js to synchronize the working directory to the .exe directory. Update env.js to parse multi-origin CORS and load .env next to the binary.

npm run build:exe

Configure Operator UI for Subpath Routing (/operator/)

In operator/src/api/axiosClient.js, update unauthenticated redirects to ${import.meta.env.BASE_URL || '/'}login. Build the production bundle.
cd operator
npm run build

3

Configure Admin Frontend for Base Routing

In frontend/vite.config.js, set base: env.VITE_BASE_PATH || '/'. In frontend/src/App.jsx, pass basename={import.meta.env.BASE_URL} to <BrowserRouter>. In frontend/src/api/axiosClient.js, dynamicize the 401 redirect URL. Build production assets.
cd frontend
npm run build
Step 4
4

Configure Nginx Web Server

Place nginx.conf and mime.types in the Nginx configuration directory (e.g., C: ginxconf). Verify static path mappings for operator/dist and frontend/dist using forward slashes (/). Validate configuration syntax.
C:\nginx\nginx.exe -t
Step 5
5

Automate Background Windows Services with NSSM

Create two background Windows Services: TriveniBackend (pointing to triveni-backend.exe) and TriveniNginx (pointing to nginx.exe). Configure automatic startup, crash recovery, and 10 MB stdout/stderr log rotation.
nssm install TriveniBackend "C:\Triveni\backend\triveni-backend.exe"
nssm set TriveniBackend AppDirectory "C:\Triveni\backend"
nssm install TriveniNginx "C:\nginx\nginx.exe"
nssm start TriveniBackend
nssm start TriveniNginx
