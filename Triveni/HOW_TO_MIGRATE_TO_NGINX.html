🏛️ Architecture Comparison: Before vs After

❌ Before (Original Codebase) Multi-Port Dev Mode
  • ⚠️
    3 Separate Node/Vite Processes: Admin UI ran on :5173, Operator UI on :5180, and Backend API on :5050.
  • ⚠️
    Vite Dev Proxy: Relied on Vite's internal node HTTP proxy to route /api and /socket.io to backend port 5050.
  • ⚠️
    CORS Vulnerabilities & Port Blocks: Shop-floor tablets accessing port 5180 or 5050 over LAN encountered firewall rejections and CORS mismatches.
  • ⚠️
    Uncompiled Assets: Ran Node dev servers in open cmd prompts without native Windows background daemonization.
✅ After (Nginx Production Deployment) Single-Port Nginx Architecture
  • 🚀
    Unified Standard Port 80: Single IP entry point for all office desktops, tablets, and kiosks.
  • 🚀
    Static Pre-Built SPAs: Both apps compiled to high-speed static assets in frontend/dist and operator/dist.
  • 🚀
    Zero-CORS Same-Origin Routing: /api/ and /socket.io/ reverse-proxied internally to backend upstream 127.0.0.1:5050.
  • 🚀
    Single Standalone Backend Executable: Packaged Node binary (triveni-backend.exe) with automatic service recovery via NSSM.

📋 Step-by-Step Implementation Playbook

STEP 1

Frontend: Subpath Routing & Base URL Configuration

Because both applications are hosted on the same domain and port (/ for Admin, /operator/ for Floor Operator), Vite and React Router must be configured to respect their root subpaths during bundle creation and history navigation.

  • In frontend/vite.config.js: Add base: env.VITE_BASE_PATH || '/'.
  • In frontend/src/App.jsx: Pass basename={import.meta.env.BASE_URL} to <BrowserRouter>.
  • In frontend/src/api/axiosClient.js: Update 401 unauthenticated redirect to ${import.meta.env.BASE_URL || '/'}login.
  • In operator/vite.config.js: Set base: env.VITE_BASE_PATH || '/operator/'.
  • In operator/src/App.jsx: Pass basename={import.meta.env.BASE_URL} to <BrowserRouter>.
  • In operator/src/api/axiosClient.js: Update 401 unauthenticated redirect to ${import.meta.env.BASE_URL || '/'}login.
STEP 2

Backend: Standalone Executable Packaging & Dynamic CORS

Configure the Node.js backend so it can run as an independent Windows .exe without requiring Node.js to be installed on target factory host machines, and ensure multi-IP LAN access works cleanly.

  • In backend/package.json: Install @yao-pkg/pkg and configure the binary build target node20-win-x64.
  • In backend/src/server.js: Synchronize working directory when packaged (process.chdir(path.dirname(process.execPath))).
  • In backend/src/config/env.js: Add parseCorsOrigin() to parse comma-delimited origins, and detect .env next to .exe.
  • In backend/.env: Add host LAN IPs to CORS_ORIGIN (e.g., http://localhost,http://192.168.1.20,http://192.168.8.8).
STEP 3

Compile Production Bundles

Build the static client bundles and the packaged backend binary. Run the following commands:

STEP 4

Deploy Nginx Configuration (nginx.conf)

Create nginx.conf in the root directory. Configure upstream triveni_backend { server 127.0.0.1:5050; }, route / to frontend/dist, route /operator/ to operator/dist, and reverse proxy /api/ and /socket.io/ with WebSocket header upgrade flags.

STEP 5

Setup Startup Automation & Windows Services

Create helper batch scripts for one-click operations:

  • start-backend.bat: Runs triveni-backend.exe if present, or falls back to node src/server.js.
  • start-nginx.bat: Launches the Nginx Windows background service.
  • stop-nginx.bat & reload-nginx.bat: Graceful stop and hot reload.
  • DEPLOYMENT_GUIDE_NSSM.txt: Configures NSSM (Non-Sucking Service Manager) for auto-start on Windows reboot.
