Decoupled Modularity

Master nginx.conf dynamically includes independent location configs (erp.locations.conf, ems.locations.conf), enabling independent lifecycle updates.

Kernel-Level Speed

Zero-CORS Single Origin

Unifies client web interfaces and backend Node.js APIs behind unified ports (80/81/82), preventing browser cross-origin preflight latency.

EMS Module

1. Mallik EMS: Industrial Energy Management System

The EMS platform provides sub-second monitoring of power meters, transformers, and heavy equipment. Nginx isolates the entire EMS frontend and backend onto dedicated Port 82, ensuring zero interference with ERP or ShopFloor operations.

Port 82 Ingress & Protocol Routing Flow

flowchart TD
    Req["Request: http://192.168.8.8:82/..."] --> Router{"URI Route Match"}
    
    Router -->|"Root: / or /EMS/ or /MallikEMS/"| Disk["Disk Serve: D:/EMS/frontend/build/build/"]
    Router -->|"/api/*"| API["Proxy Pass: http://127.0.0.1:8005/api/"]
    Router -->|"/socket.io/*"| WSS["WebSocket Upgrade: http://127.0.0.1:8005/socket.io/"]
    Router -->|"/public/*"| Pub["Static Media Proxy: http://127.0.0.1:8005/"]
    
    Disk -->|"SPA Fallback"| Index["try_files $uri $uri/ /index.html"]

Key Nginx Directives & Production Rationale

Directive & Parameter Scope / Location Technical Purpose & Industrial Impact
listen 82; server block Binds explicitly to port 82 on 192.168.8.8 and localhost, allowing side-by-side execution with ERP (80) and ShopFloor (81).
client_max_body_size 500m; Global & server Overrides Nginx's default 1MB buffer to permit multi-megabyte smart meter batch telemetry dumps and firmware OTA files.
try_files $uri $uri/ /index.html; location /, /EMS/ Single Page Application (SPA) routing: ensures client-side deep links (e.g. :82/EMS/meter/42) load without triggering 404 Not Found errors on browser refresh.
proxy_set_header Upgrade $http_upgrade;
proxy_set_header Connection "upgrade";		 location /socket.io/ Performs bidirectional HTTP/1.1 WebSocket handshakes required by Socket.IO for streaming real-time KEB energy data and meter alerts.
proxy_read_timeout 300s; /api/ & /socket.io/ Extends the connection timeout to 5 minutes, preventing Gateway Timeouts during intensive monthly energy aggregation SQL queries.

Production Configuration Snippet (ems.locations.conf)

server { listen 82; server_name 192.168.8.8 localhost _; client_max_body_size 500m; # 1. Frontend Production Build (Direct Disk Serving with SPA Fallback) location / { root "D:/EMS/frontend/build/build"; index index.html; try_files $uri $uri/ /index.html; } location ^~ /EMS/ { alias "D:/EMS/frontend/build/build/"; index index.html; try_files $uri $uri/ /EMS/index.html; } # 2. REST API & WebSocket Streaming Reverse Proxy location /api/ { proxy_pass http://127.0.0.1:8005/api/; proxy_http_version 1.1; proxy_set_header Host $host; proxy_read_timeout 300s; } location /socket.io/ { proxy_pass http://127.0.0.1:8005/socket.io/; proxy_http_version 1.1; proxy_set_header Upgrade $http_upgrade; proxy_set_header Connection "upgrade"; } }

Module Deep Dive • Dual-Port ERP Integration
ERP & ShopFloor

2. Mallik ERP (Port 80) & ShopFloor (Port 81)

This architecture replaces legacy XAMPP Apache with an event-driven Nginx deployment. It concurrently hosts the primary Enterprise Resource Planning (ERP) application alongside the new factory ShopFloor execution platform.

Legacy Apache / XAMPP Bottlenecks ❌

  • Thread Exhaustion: Apache's mod_proxy spawns OS threads per request, exhausting RAM under concurrent industrial usage.
  • Fragile Monolith: Apache crash cascades took down bundled MariaDB databases.
  • Complex Rewrites: Fragile .htaccess regular expressions required for SPA routes.

Production Nginx Architecture ✅

  • Non-Blocking Event Loop: Handles 10,000+ simultaneous connections with only ~15 MB RAM.
  • Isolated MariaDB Service: Database runs as a native Windows Service independent of web servers.
  • Kernel sendfile: High-speed zero-copy static asset delivery directly from disk.

Automated PowerShell Deployment Workflow (deploy.ps1)

Deployment Stage Action Performed Industrial Safety & Verification
1. Firewall Provisioning New-NetFirewallRule -LocalPort 81 -Protocol TCP Guarantees shop-floor machine tablets on the 192.168.8.x LAN can communicate with port 81.
2. Configuration Backup Copy-Item nginx.conf nginx.conf.bak_TIMESTAMP Generates an immediate rollback point before applying new location includes.
3. Syntax Validation nginx.exe -t Strict pre-flight test; prevents restarting Nginx with invalid directives or unreadable paths.
4. Zero-Downtime Reload nginx.exe -s reload Swaps configuration dynamically in worker memory without dropping active ERP user sessions.
MAC Address Hardware Locking Protection: The backend services in ShopFloor enforce client MAC validation. When deploying via Nginx, proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; guarantees client hardware addresses are preserved for audit logging.

3. Triveni MES: Factory Floor & Upstream Clustering

Triveni MES runs production lines in steel manufacturing plants. Nginx serves two distinct Vite Single Page Applications over a single port (80) while maintaining persistent upstream connections to an Express & Socket.IO telemetry cluster.

Single-Port Dual-SPA & Upstream Topology

flowchart TD

    PathCheck -->|"/operator/*"| OperatorSPA["Operator Touch Kiosk SPA

    PathCheck -->|"Default: /*"| AdminSPA["Management Portal SPA
(frontend/dist/index.html)"]
    PathCheck -->|"/api/*"| Pool["upstream triveni_backend
(127.0.0.1:5050 - keepalive 32)"]
    PathCheck -->|"/socket.io/*"| SocketPool["Live Telemetry WebSockets
(Coil counters, OEE, downtime)"]
    PathCheck -->|"/health"| HealthCheck["Micro Health Probe (:5050/health)"]

Operator Kiosk vs Admin Routing

Operator UI (/operator/) runs on tablet touchscreens mounted to steel slitting machines, optimized for high-contrast viewing and big-button checklist inputs.
Admin Portal (/) delivers heavy analytics, shift scheduling, CAPA tracking, and coil inventory management.

Upstream Persistent Keepalive

By declaring upstream triveni_backend { server 127.0.0.1:5050; keepalive 32; }, Nginx preserves an active pool of 32 reusable TCP connections, cutting TCP handshake latency to nearly zero during bursty machine sensor transmissions.

Production Configuration Extract (Triveni/nginx.conf)

upstream triveni_backend { server 127.0.0.1:5050; keepalive 32; # Keeps connection pool open to Node.js backend } server { listen 80; server_name 192.168.1.20 192.168.8.8 localhost _; # 1. Operator Web App (Shop-Floor Touch Kiosk) location ^~ /operator/ { alias "C:/Developer_19_Projects/Nginx demo/Triveni/operator/dist/"; index index.html; try_files $uri $uri/ /operator/index.html; } # 2. Management & Admin Portal (Default Root SPA) location / { root "C:/Developer_19_Projects/Nginx demo/Triveni/frontend/dist"; index index.html; try_files $uri $uri/ /index.html; } # 3. High-Throughput API & Socket.IO Reverse Proxy location /api/ { proxy_pass http://triveni_backend/api/; proxy_http_version 1.1; proxy_read_timeout 300s; } location /socket.io/ { proxy_pass http://triveni_backend/socket.io/; proxy_http_version 1.1; proxy_set_header Upgrade $http_upgrade; proxy_set_header Connection "upgrade"; } }

Full-Stack Patterns

4. Js Based App: Zero-CORS Architecture Pattern

In modern frontend engineering, developing React and Node.js on separate development ports (e.g. 5173 and 5000) causes CORS (Cross-Origin Resource Sharing) issues. The Js Based project demonstrates how Nginx completely eliminates CORS in production.

CORS Elimination Flow

flowchart TD
    Browser["Browser Client (Port 80)"] --> Nginx["Nginx Reverse Proxy (:80)"]
    Nginx -->|"fetch('/api/dashboard')"| Backend["Node.js Express (:5000)"]
    Nginx -->|"Static files"| Dist["client/dist/"]

Code Decoupling Benefit

// Before: Hardcoded local backend port const URL = "http://localhost:5000/api/dashboard"; // After: Clean relative path (Nginx handles routing) const URL = "/api/dashboard";

Frontend code never needs environment-specific backend hostnames. The browser considers /api same-origin, saving HTTP OPTIONS pre-flight handshakes.

Operations Manual • Troubleshooting Matrix
Operations & Runbook

1. Master Nginx Directives Cheatsheet

Directive Recommended Setting Industrial Architecture Impact
sendfile on; http context Enables DMA (Direct Memory Access) kernel copying, bypassing user-space buffer allocation for static assets.
keepalive_timeout 65s; Maintains persistent TCP connections with browsers, eliminating TLS/TCP renegotiation overhead.
gzip_types text/plain application/json application/javascript ... Reduces React/Vite bundle sizes by up to 75% over factory Wi-Fi and cellular networks.
proxy_http_version 1.1; Mandatory for HTTP Keepalive and WebSocket handshakes; avoids HTTP/1.0 connection tearing.

2. Production Troubleshooting Matrix

Observed Issue Root Cause Remediation Action
502 Bad Gateway Backend Node.js or Flask process is stopped, crashed, or listening on an incorrect port. Verify backend is active with Get-NetTCPConnection -LocalPort 5050 or restart service via batch scripts.
404 on Refresh Missing try_files directive in Nginx for React Router client routes. Add try_files $uri $uri/ /index.html; inside the corresponding frontend location block.
413 Payload Too Large File upload exceeds the default 1MB Nginx buffer limit. Set client_max_body_size 500m; in the server or http block and reload Nginx.
WebSocket Drops Missing connection upgrade headers or aggressive proxy timeouts. Ensure Upgrade $http_upgrade and Connection "upgrade" are present and set proxy_read_timeout 300s;.
